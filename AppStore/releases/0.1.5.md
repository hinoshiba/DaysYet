# 0.1.5 (8) iOS・macOSリリース記録

iOS / iPadOSとmacOSの **0.1.5 (8)** を2026-09-11に審査提出し、両方とも「審査待ち」を確認しました。提出時刻はiOSが22:35 JST、Macが22:48 JSTです。承認後の自動公開を維持しています。Appleによる承認と公開は未確認です。以前の提出状況は[0.1.4 (7)の記録](0.1.4-build7.md)に残しています。

## 変更内容

- 両プラットフォームに「学習日」を追加。名前と開始日・終了日を設定し、曜日で一括選択後にカレンダーの日付を追加・除外できる。両端を含めて最長366日で、2週間・4週間のショートカットを用意。
- 学習日の残りは選択された今日を含み、経過割合は過去になった選択日数を全選択日数で割った値。学習実績や完了の記録ではない。予定未選択と予定終了を区別し、端末の予定表へのアクセスは行わない。既存の表示項目は保持。
- iOS / iPadOSでは「設定 → 時間の基準 → 学習日を選ぶ」から編集し、アプリとホーム画面・ロック画面のウィジェットに表示できる。ホーム画面の表示項目数はこれまでどおり3つ、ロック画面は1つ。
- Macの円形メーターは標準の3つから、学習日を含む重複しない8種類まで追加でき、最小は3つ。左右ではすべてを表示し、上端・カメラ下では一覧の上から3つだけを表示・選択する。4つ目以降の設定は保持。
- Macでは表示中の時間ごとに色を選択可能。4つの配色テンプレート、個別の色リセット、全体のリセットを用意。テンプレートの選択は全項目のカスタム色を置き換える。変更は即時反映・保存。
- Macの「設定 → ウィジェット」の先頭に「ログイン時に起動」を追加。利用者が有効・無効を変更でき、承認待ちや変更失敗時にはmacOSのログイン項目設定を開ける。システム設定の変更はアプリに戻ると反映。
- Mac設定の上下位置スライダーを削除。左右の本体をドラッグして上下位置を調整する操作、位置の保存、中央に戻す操作を維持。
- iOS / iPadOSのアプリ、Widget、テストと、Macのアプリ、テストのバージョン・ビルド番号は0.1.5 (8)で統一。

## Archiveと配布物

Archive元は、[PR #19](https://github.com/hinoshiba/DaysYet/pull/19)でmainへ取り込まれた`eb4cac26d697bf8c41447809eca9482a5c6be20d`。[そのコミットのCI](https://github.com/hinoshiba/DaysYet/actions/runs/34593875366)は成功し、マージコミット`93c8300e2f2c42732807dd7d5218fc6b5e198484`とのGit tree一致を確認。両方とも追跡ファイルが未変更の専用チェックアウトから、ローカルXcodeのProduct > Archiveで作成した。

Xcode 26.6 (17F113)と各26.5 SDKを使用。iOSは22:23 JST、Macは22:30 JSTのArchiveを採用。iOSはDaysYet / Any iOS Device、MacはDaysYetMac / Any Mac、いずれもRelease構成。最初の22:20のiOS Archiveは採用・アップロードしていない。

- iOS本体とWidgetは0.1.5 (8)・iPhoneOS / arm64・iOS 17以降・iPhone/iPad対応。Archiveの署名、プロファイルとApp Group・権限の整合、ソースと一致するPrivacy Manifest、dSYM UUID一致を確認。
- iOS配布物は既存のCloud Managed Apple Distribution署名。アプリとWidgetのApp Store用プロファイルと権限が整合し、`get-task-allow`は無効。IPA全33ファイルと配布用ステージングが一致し、リソースとシンボルもArchiveと整合。Organizer Validateは22:26 JSTに全検証成功、アップロードは22:29 JSTに成功。
- MacのArchiveはDaysYet.app、0.1.5 (8)、arm64とx86_64を含むUniversal。署名検証、App Sandbox、Hardened Runtime、両アーキテクチャのdSYM UUID一致、ソースと一致するPrivacy Manifestを確認。
- Macは既存のMac App DistributionとMac Installer Distributionを手動で選択。配布アプリの権限はApp Sandboxのみ。配布PKGから展開したアプリは署名済みステージングと全ファイル一致し、16リソース、翻訳、Privacy Manifest、両アーキテクチャとシンボルがArchiveと整合。22:33 JSTのValidateはTestFlight用プロビジョニングプロファイルがないという警告のみで完了した。22:37 JSTにアップロード成功を確認。今回のsandbox-only構成では前回同様のMac App Store経路を使い、TestFlight利用条件を満たしたとは扱わない。
- 両方ともシンボルを含め、バージョン・ビルド番号の自動変更とTestFlight内部テスト限定を無効にした。署名済みアーカイブ、配布物、プロファイルと配布ログは公開ソースに含めない。
