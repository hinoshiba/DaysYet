# 0.1.6 (10) remaining-time countdown

This candidate updates iPhone / iPad, its Widget extension, and the native Mac
app to 0.1.6 (10). It includes the Mac hover and detail-size features prepared
in [0.1.6 (9)](0.1.6-macos.md), plus the remaining-time changes below.
The existing `v0.1.6` tag belongs to build 9 and is not reassigned.

## Behavior and review

- Percentages, colored bars, rings, and accessibility descriptions represent
  time remaining, decreasing from 100% to 0%. Bars retain their left edge;
  circles empty clockwise from 12 o’clock. Completed periods have no colored
  remainder. Inactive schedules retain Off, and empty study plans have no budget.
- Calendar periods refill at the next period boundary. Study days include
  today when selected. Existing dates, schedules, widget overrides, and saved
  display-mode values are preserved.
- Independent review found and fixed integer rounding that could turn exact
  10% into 9% in Mac rings. Positive values below display precision show <1%
  or <0.1%, distinct from depleted 0%.
- Japanese and English app, website, and store explanations now describe the
  remaining amount. Website review also corrected navigation instructions,
  activity defaults, and stale labels after switching languages.

## Candidate validation

Xcode 26.6 (17F113) passed 89 iOS tests, 191 Mac tests, and three iOS UI
tests after the precision fix. Coverage includes all metric types, start/end boundaries, period resets,
Off/empty schedules, overnight activity, DST, selected study days, accessibility,
and saved-setting compatibility. Four additional precision regression tests
cover exact 10%, a small healthy-goal balance, formatting thresholds, and the
last available day in a 366-day study plan.

The candidate uses synthetic screenshot data and temporary preferences for
visual verification. Current screenshot provenance is recorded in the
[App Store preparation notes](../README.md) and [Mac screenshot notes](../macos/screenshots/README.md).
Unsigned local checks do not establish upload or App Review submission.

The unchanged Lock Screen circular subview was rendered with iOS SwiftUI
and WidgetKit at 62 points. Visual checks passed for 0%, 0.5% (displayed as
<1%), 25%, 75%, 100%, and Off, including the clockwise depletion direction
and text fit. This is a native subview rendering check, not a live WidgetKit
host capture. The simulator did not expose Lock Screen customization, and
the Home Screen widget remained in its initial loading view during the bounded runtime
check; live host delivery was not established by that check.

Release compliance (including live support/privacy URL checks) passed. A
redacted scan of the existing 42-commit Git history found no secrets. Xcode
Cloud showed its setup screen with no configured workflow.
